---
name: resolving-merge-conflicts
description: 当你需要解决正在进行的 Git merge 或 rebase 冲突时使用。
---

1. **查看 merge / rebase 的当前状态。** 检查 Git 提交历史以及存在冲突的具体文件。

2. **寻找各个冲突的一手来源。** 深入理解每边变更做出的根本原因以及最初的设计意图。阅读 Commit 提交信息，检查相关 PR，查阅原始 Issue 或 Ticket。

3. **逐块解决冲突 (Resolve each hunk)。** 在可行的情况下尽可能兼顾保留双方意图。当双方意图无法调和时，选择契合本次合并声明的核心目标的一方，并记录相应权衡。**切勿**凭空捏造全新的行为。始终坚持化解；绝不执行 `--abort`。

4. 探测项目的**自动化检查工具**并运行它们，通常按类型检查、测试套件、代码格式化的顺序执行。修复合并过程中破坏的任何问题。

5. **完成 merge / rebase。** 将所有已解决文件暂存（Stage）并提交。若是 Rebase 操作，继续执行 rebase 流程直到所有 Commit 均完成变基。
