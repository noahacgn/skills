---
name: grilling
description: 针对计划、决策或构想对用户进行深度盘问。当用户希望压力测试其思路，或使用任何带有“grill”的触发短语时使用。
---

对用户进行深度访谈，直至双方达成共识。将其映射为**决策树 (design tree)**：每个决策都会衍生出挂载在其之下的后续决策。

按**轮次 (rounds)** 推进决策树。**前沿边界 (frontier)** 是指前置条件均已确定的所有决策：即你*当前*即可提出、而无需胡乱猜测未收到答案的问题。在一轮中提完整个前沿边界的问题：为每个问题编号并给出你的推荐答案。然后等待用户回答后再开启下一轮。

每轮问题的格式应如下所示：

```
🐰 **1** - **<问题标题>**: <问题正文，可包含多个段落，包括多项选择>

🥕 <你的推荐答案>

---

🐰 **2** - **<问题标题>**: <问题正文，可包含多个段落，包括多项选择>

🥕 <你的推荐答案>
```

用户每回答一轮都会重塑决策树：已确定的决策会将前沿边界向外推进，并解锁依赖它们的问题。重新计算前沿边界并提出下一轮问题。若某个问题的答案依赖于本轮仍未决的其他问题，则该问题属于*后续*轮次，而非本轮。

寻找*事实*是你的职责，绝非用户的职责。当前沿边界的问题需要来自环境的事实（文件系统、工具、外部 API 等）时，派发子 Agent 去查找；切勿向用户询问你自己就能查到的任何信息。*决策*属于用户：将每个决策摆在用户面前并等待回复。

当前沿边界为空时，会话即告结束：决策树的每个分支均已被遍历，没有遗留任何未经证实的默认假设。在用户确认达成共识之前，不要直接付诸行动。
