# 学习记录格式规范 (Learning Record Format)

学习记录存放在 `./learning-records/` 下，使用连续编号：`0001-slug.md`、`0002-slug.md` 等。该目录按需延迟创建，仅在写入第一条记录时生成。

它们相当于教学领域的架构决策记录 (ADR)：记录非直观的经验沉淀、核心见解以及用户明确说明的既有知识背景，用于指导未来的会话，并用于计算最近发展区。

## 模板

```md
# {所学到或确立认知的一句话标题}

{1-3 句话：学到了什么（或确立了怎样的既有知识背景），以及为什么它对未来的会话至关重要。}
```

这就是全部格式要求。一条学习记录可以只是一个段落。其价值在于记录*已知*该事实，并说明*为什么*它会改变接下来要传授的内容，而非机械地填充各个小节。

## 可选小节

仅在确实能带来实质价值时包含以下小节，大部分记录无需使用：

- **Status** 元数据 (`active | superseded by LR-NNNN`)，当早期的理解被证实不够准确并被新认知取代时非常有用。
- **Evidence**：用户如何证明了其掌握程度（回答了某个问题、完成了某项练习、引用了既往经验）。当该论断后续可能需要复核时非常有用。
- **Implications**：这为后续会话解锁了哪些可能，或排除了哪些方向。在影响并非显而易见时值得记录。

## 编号规则

扫描 `./learning-records/` 中现有的最大编号并在此基础上加一。

## 何时编写学习记录

满足以下任一条件时，应当编写一条学习记录：

1. **用户展示了对非浅显内容的真正理解**：不仅仅是接触过，而是有证据表明其能正确运用该概念。这为后续教学确立了全新的认知基线。
2. **用户说明了既有知识**：“我已经了解 X 了。”记录下来以避免后续会话重复教学，同时记录其声称的*掌握深度*。
3. **纠正了误解**：用户先前抱有某种错误认知，现在理解了原因。这些记录价值极高：能预测用户在后续相关主题上可能遇到的障碍。
4. **使命随学习发生转移**：用户发现自己真正关心的方向与起初设想的不同。交叉链接至 [[MISSION.md]] 并予以更新。

### 哪些情况不符合编写标准

- 仅仅是涉及或覆盖过的内容。覆盖不等于掌握。等待证据呈现。
- 已在 [[GLOSSARY.md]] 中简短定义过的术语。不要重复记录。
- 逐会话的活动日志。学习记录不是日记，它是达到决策级别的深度洞见。

## 记录更替 (Supersession)

当后续记录与早期记录相冲突时（用户的理解加深或得到修正），将旧记录标记为 `Status: superseded by LR-NNNN`，而不是直接删除。理解演进的历史本身就是宝贵的参考信号。
