# 技能机制规范 (Skill mechanics)

[`writing-for-agents`](SKILL.md) 的 Skill 特化分支：阐述当文档作为一项 Skill 时的特殊要点，Frontmatter 编写、触发方式选择以及路由技能（Router skills）。关于编写文档的其他通用规范，请参考 `SKILL.md`。

## 触发机制 (Invocation)

两种选择，分别在两种负载间进行权衡：

- **模型触发 (Model-invoked)** 技能保留 `description`，使 Agent 能够自主调用，其他技能也能够调用它。你依然可以手动输入其名称进行调用：模型触发始终*包含*用户调用能力；添加描述只会增加 Agent 的发现能力，绝不会剥夺人类的调用权。描述是 Skill 顶层的上下文指针，必须时刻保持加载状态，以永久的上下文负载换取可发现性。对于内容全为参考资料的模型触发技能，它也是共享参考资料的归宿之一：其他技能可以调用它，从而使多个技能所需的参考内容集中在一处。机制：省略 `disable-model-invocation`，并编写面向模型的描述，其中包含触发分支（`SKILL.md` 中的指针编写规则完全适用）。
- **用户触发 (User-invoked)** 技能从 Agent 的视野中剔除了描述：只有人类手动输入其名称才能调用，任何其他技能都无法调用。零上下文负载，但消耗认知负载，你需要记住它的存在。机制：配置 `disable-model-invocation: true`；其 `description` 转为面向人类，精简为单行摘要，剔除触发词列表。

仅在 Agent 必须自主调用该技能、或需要由其他技能调用时，才选择模型触发。如果它始终只通过手动触发，请设为用户触发，无需承担任何上下文负载。

两项用户触发技能共同需要的共享参考资料不能存放在任何一方之中，由于没有描述，双方都无法调用对方。应将其提取到技能系统之外的独立文件中：作为任何技能都能引用的外部参考资料。

## 按触发方式拆分 (Splitting by invocation)

拆分中的触发维度切割（按顺序拆分参见 `SKILL.md`）：当你拥有一个独立的引导词，且应当单独触发该技能时（即你在提示词中确实会用到的触发词），或者有其他技能必须调用它时，将其拆分为一个模型触发技能。你将为新增的常驻描述付出上下文负载，因此这种独立的调用价值必须物有所值。

## 路由技能 (Router skills)

当用户触发的技能数量多到超出你的记忆负荷时，这种堆积的认知负载可以通过**路由技能 (router skill)** 来化解：设计一个用户触发技能，在其中列出其他技能以及何时应当调阅哪一个，这样人类只需要记住一个技能即可。它只能提供指引，绝不能直接调用它们：用户触发技能没有描述，除了人类之外任何机制都无法调用它们。
